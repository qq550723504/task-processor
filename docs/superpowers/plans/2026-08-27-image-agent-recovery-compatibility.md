# Image Agent Recovery and Compatibility Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Use `superpowers:test-driven-development` for every behavior change and `superpowers:verification-before-completion` before each commit.

**Goal:** Make the manual Image Agent workflow safely upgradeable and recoverable across Temporal replay, activity retries, concurrent publication, and Kubernetes Pod replacement, while exposing actionable failures to the workbench.

**Architecture:** Add a v3 external-effect protocol in `internal/imageagent`, backed by a new additive GORM table and the existing S3-compatible storage configuration. Provider output is converted to an immutable staging manifest before it can be considered durable. Publication uses a database lease and fencing token plus deterministic object keys. Frozen v2 handlers and independent Temporal version markers preserve old history; new runs use a dedicated v3 task queue.

**Tech Stack:** Go 1.26, GORM 1.31.1, Temporal Go SDK 1.43.0, AWS SDK for Go v2, Gin, React 19, Next.js 16, Vitest, Kubernetes/Kustomize.

**Spec:** `docs/superpowers/specs/2026-08-27-image-agent-recovery-compatibility-design.md`

**Baseline:** `27ba3b060`

## Global constraints

- This slice hardens manual mode only. Do not implement Agent planning or automatic repair.
- Keep `imageagent` domain files free of Temporal, AWS SDK, GORM, HTTP, ListingKit, and ProductImage implementation imports.
- Treat every existing `.v2` Temporal name and payload as immutable. Never point `imageagent.execute_slot.v2` at v3 behavior.
- Use a new `image_agent_v3_slot_external_effects` table. Do not reinterpret or backfill v2 effect rows in normal runtime code.
- Never persist a Pod-local path, generated bytes, credentials, arbitrary provider metadata, or transient provider URL.
- Use the configured S3/COS client and AWS SDK operations; do not implement an object-storage protocol.
- A timeout is not proof that an external call failed. Reconcile deterministic object identity before retrying.
- Do not claim physical exactly-once execution. The acceptance boundary is one durable observable result.
- Preserve the existing no-global-ten-image-limit behavior.
- Preserve unrelated changes and stage only paths listed by the current task.
- Do not push, open a PR, deploy, or mutate production from this plan unless the user separately authorizes it.

- [ ] **Step 3: Implement `ExecuteSlotV3` as an explicit phase interpreter**

The activity may perform only the operation authorized by persisted phase:

- newly created `provider_claimed`: call provider once, prepare manifest, persist it;
- `staging_prepared`: stage or reconcile objects, then commit staged state;
- `artifact_staged`: acquire publication claim;
- current `publication_claimed`: finalize or reconcile deterministic final objects;

- unknown phases: return a typed non-retryable application error.

Derive publication owner identity from Temporal workflow run ID, activity ID, and activity attempt. Renew a current lease around bounded multi-object operations. Also validate main-slot cardinality in `PersistSlotResult`, so a non-ProductImage executor cannot bypass the adapter check. Zero or multiple candidates for a main slot become `invalid_main_candidate_count` and cannot enter an accepted projection.
