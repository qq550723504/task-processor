# Studio 手动重新抠图与双图预览设计

## 目标

在 SHEIN Studio 的款式审核卡片中，为每个生成款式提供“重新抠图”操作，并同时展示普通生成原图和透明背景抠图结果。该操作只处理现有图片，不重新生成款式。

## 现状与边界

- 项目已有 `StudioBackgroundRemover`、抠图状态字段和批次抠图重试接口。
- 现有接口只接受 `transparent_background_mode=removal` 且已有 `original_image_url` 的设计，因此普通生成图无法主动触发抠图。
- `SheinDesignLightbox` 已支持原图/最终图切换；卡片当前只显示 `imageUrl`。
- 本次只覆盖 Studio 审核页的设计图，不改变商品图生成、SHEIN 资料生成或重新生成款式流程。

## 方案

复用现有 `POST /api/v1/listing-kits/studio/batches/:batch_id/designs/background-removal/retry` 接口并扩展其语义，使其同时支持手动首次抠图和失败重试。保留原路径以兼容现有客户端，不新增重复接口。

### 后端数据流

请求携带一个或多个 `design_ids`，每个目标按以下规则处理：

1. 使用已持久化的 `original_image_url` 作为抠图输入；如果为空，则使用当前 `image_url`，并先将它保存为 `original_image_url`。
2. 将 `transparent_background_mode` 设为 `removal`，状态设为 `pending`，清除上一次错误和模型信息并持久化。
3. 调用现有 background-removal 模型。
4. 成功时将新透明 PNG 写入 `image_url`，保留 `original_image_url`，状态设为 `succeeded`，记录模型。
5. 失败或返回空结果时将 `image_url` 回退为原图，保留 `original_image_url`，状态设为 `failed`，记录错误；接口仍返回最新批次详情，让 UI 能显示失败状态。

重复点击永远从持久化原图开始，不会把已经抠图的结果再次作为输入。没有图片地址的设计返回校验错误，不创建半成品状态。

### 前端卡片

`SheinDesignPreviewGrid` 在非只读审核状态下为每张设计显示“重新抠图”按钮。按钮执行期间禁用当前设计并显示“抠图中...”，同时保留现有“重新生成”按钮的独立状态。

卡片预览区域改为两个并排、响应式的图片面板：

- “原图”：使用 `originalImageUrl`；没有该字段时使用当前 `imageUrl`，代表尚未建立抠图前的输入图。
- “抠图后”：只有存在成功的抠图结果时显示 `imageUrl`；尚未处理时显示“尚未抠图”，处理中显示“抠图处理中”，失败时显示“抠图失败，当前显示原图”。

原图和抠图结果使用同一套 URL 规范化和缩略图处理，避免已认证上传地址再次被错误代理。抠图状态标签和错误信息保留在两张图上方或下方，避免用户把失败回退误认为成功透明图。

只读审核页不显示操作按钮，但仍显示已有的原图/抠图后双图结果。大图预览继续复用 `SheinDesignLightbox` 的原图/最终图切换，并使用明确的“原图”和“抠图后”文案。

### 状态更新与错误处理

点击后调用现有批次详情接口，成功返回后用完整详情刷新当前 hydrated batch，保证卡片、选中状态和后续创建任务使用同一份数据。请求失败时不覆盖现有图片，只在页面错误提示中说明“重新抠图失败”。

在成功抠图前，原图始终可查看；失败时 `image_url` 回退到原图，`original_image_url` 不丢失，用户可以再次点击“重新抠图”。

## 测试设计

### 后端

- 普通生成设计没有 `original_image_url` 时可以手动抠图，并把原 `image_url` 保存为原图。
- 已有抠图结果时再次处理仍使用持久化原图，而不是最终图。
- 抠图失败时保留原图、状态为 `failed` 并记录错误。
- 无图片地址或请求了不存在的设计时返回明确校验错误。

### 前端

- 有原图和抠图结果时卡片同时渲染两个有标签的图片。
- 没有抠图结果时显示“尚未抠图”，并且“重新抠图”按钮可用。
- 点击“重新抠图”触发对应设计 ID，并在处理中禁用当前按钮。
- 只读状态仍能查看双图，但不显示操作按钮。
- Lightbox 继续正确切换并规范化原图和最终图 URL。

## 验收标准

1. 审核页每个可操作款式都能点击“重新抠图”，不需要重新生成。
2. 抠图完成后，卡片能同时看到普通原图和透明背景结果。
3. 重试不会以已抠图结果作为输入，失败不会丢失原图。
4. 现有重新生成、批准、创建 SHEIN 资料和只读审核流程行为不变。
5. 后端相关测试和前端 Studio 测试通过，且完成类型检查、构建和 diff 检查。
