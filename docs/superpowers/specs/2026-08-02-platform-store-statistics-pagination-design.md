# 平台店铺上架统计分页设计

## 背景

`/listing-kits/admin/store-statistics` 当前只按当前租户范围查询，并直接返回全部店铺数组。平台管理员因此看不到其他租户的店铺；当店铺数量增加时，接口响应、数据库查询和前端渲染都会随数据量增长。

## 目标

- 平台管理员页面展示所有租户下符合条件的自动上架店铺统计。
- 通过服务端分页控制响应大小和页面渲染量。
- 保留顶部统计汇总，并确保汇总值覆盖全部店铺，而不是仅覆盖当前页。
- 租户端 `/listing-kits/store-statistics` 继续遵循当前租户可见范围。
- 复用现有店铺列表的分页约定：`page`、`page_size`、`items`、`total`。

## 方案

### 权限和数据范围

平台统计路由调用现有的平台店铺权限标记。统计 Handler 在检测到平台店铺权限后清除 `TenantID` 和 `OwnerUserID`，查询所有租户的有效、启用自动上架且启用自动登录的店铺。

租户统计路由不设置平台权限标记，因此继续使用请求中的租户和用户范围。

### 后端接口

将 `StoreStatisticsQuery` 增加 `Page` 和 `PageSize`。分页参数通过现有列表范围解析，默认页码为 1、每页 20 条，沿用已有最大每页 200 条的限制。

接口响应从数组改为分页对象：

```json
{
  "items": [],
  "total": 128,
  "page": 1,
  "page_size": 20,
  "summary": {
    "completed_count": 100,
    "daily_limit": 500,
    "remaining_count": 20,
    "queued_count": 8,
    "hold_count": 0
  }
}
```

`items` 只包含当前页店铺；`total` 是全部符合范围的店铺数；`summary` 对全部符合范围的店铺聚合，避免分页后页面顶部指标只反映当前页。

店铺排序保持稳定，按店铺 ID 升序。日期过滤继续作用于任务统计，不改变店铺范围筛选规则。

### 前端页面

统计 API 客户端改为解析分页对象。页面增加页码、上一页、下一页和每页数量控制，并把 `page`、`page_size` 纳入 React Query 查询键。

日期或页面大小变化时回到第 1 页；当数据刷新后当前页超出总页数时，回退到最后有效页。表格只渲染 `items`，顶部店铺数和汇总指标使用后端 `total` 与 `summary`。

复用现有 ListingKit 页面中的分页交互样式，不新增通用分页组件。

## 测试

- 后端 Handler 测试：平台权限跨租户查询；租户端仍按租户范围查询；分页参数正确传递；响应包含分页元数据和全量汇总。
- 后端 Repository 测试：分页结果、总数、边界页码，以及汇总不受当前页影响。
- 前端 API 测试：解析分页响应，拒绝旧的裸数组响应。
- 前端组件测试：显示当前页数据、分页控件、总店铺数和全量汇总；日期或页大小变化重置页码。
- 完成后运行相关 Go 测试、ListingKit UI 定向测试、TypeScript 类型检查和 `git diff --check`。

## 非目标

- 不改变租户端统计的权限模型。
- 不增加导出、筛选、排序等新功能。
- 不修改店铺或任务统计的业务口径。
