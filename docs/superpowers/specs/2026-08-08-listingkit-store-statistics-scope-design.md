# ListingKit 店铺统计权限范围设计

## 背景

`/listing-kits/store-statistics` 与管理端统计接口复用了同一条后端路径。当前后端遇到平台管理员时会绕过租户条件，因此“我的上架统计”可能展示全平台数据；同时历史店铺存在空 `owner_user_id`，不能根据旧的 `creator` 数字值安全推断当前登录用户。

## 目标

1. 租户统计接口只返回当前租户允许看到的数据，即使调用者具有平台角色，也不因角色自动扩大到全平台。
2. 平台全局统计使用显式的独立接口和页面调用路径。
3. 保持店铺归属权限的安全边界：租户管理员查看本租户全部有效店铺，普通操作员只查看本人归属的店铺；历史无归属店铺不自动分配给任何人。
4. 用回归测试锁定租户、平台和店铺归属范围。

## 非目标

- 不直接修改生产库中的 `owner_user_id`。
- 不把历史 `creator` 字段批量转换成当前用户 ID；两者不是经过验证的同一身份体系。
- 不改变统计指标的计算方式，仅修正数据范围。

## 方案

### 后端接口

- 保留 `/api/v1/listing-kits/admin/store-statistics` 作为租户统计接口。它始终使用请求上下文中的租户范围，并继续应用店铺归属规则。
- 新增 `/api/v1/listing-kits/platform/store-statistics` 作为平台统计接口。它只允许平台权限，显式清除租户和店铺所有者范围后统计全平台数据。
- 将平台统计页面的 API 调用切换到新接口；租户页面继续调用现有租户接口。

### 店铺归属

- 租户管理员：当前租户内全部有效店铺。
- 普通操作员：当前租户内 `owner_user_id` 等于当前用户的店铺。
- `owner_user_id` 为空的历史店铺：不展示给普通操作员，只由租户管理员看到，后续通过明确的归属维护流程逐店分配。

### 兼容性

现有租户统计调用方不需要改 URL；平台页面改用新增的显式 URL。平台管理员若打开租户页面，将按该页面的租户上下文查看，不再隐式获得全局数据。

## 验收标准

- 后端测试证明：租户统计不会因为平台角色而清除租户范围。
- 后端测试证明：平台统计显式使用全局范围。
- 前端测试证明：租户页面和平台页面调用不同的接口。
- 定向后端、前端测试通过，工作树只包含本次权限范围修复及其测试/设计文档。
