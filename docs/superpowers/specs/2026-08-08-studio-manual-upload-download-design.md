# Studio 生成原图下载与手动抠图上传设计

## 目标

在 SHEIN Studio 款式审核卡片中增加两项能力：用户可以下载生成时的普通原图，也可以上传自己处理好的透明 PNG 作为“抠图后”结果。手动结果必须持久化，刷新页面后仍可继续批准并生成 SHEIN 资料。

## 范围与边界

- 下载只针对“原图/生成图”，不提供“抠图后”结果下载按钮。
- 手动上传只接受 PNG；浏览器的 `accept` 只是体验限制，后端必须按实际图片格式再次校验。
- 保留现有原图/抠图后双图预览、自动抠图、重试、批准和 SHEIN 资料生成流程。
- 不新建图片存储，复用现有上传存储、租户隔离、图片代理和设计图片字段。
- 手动上传期间不能覆盖正在进行的自动抠图结果。

## 方案

使用一个 Studio 专用 multipart 变更接口，避免前端先上传通用资源、再绑定设计时留下孤立文件：

`POST /api/v1/listing-kits/studio/batches/:batch_id/designs/:design_id/manual-background-removal`

请求包含一个 `file` 字段。接口内部复用现有图片存储服务完成保存，再使用已有的图片字段局部更新边界写入设计结果。自动抠图仍使用原有重试接口，两者语义清晰分离。

## 后端数据流

1. 校验批次和设计关系，并拒绝当前处于自动抠图 `pending` 状态的设计。
2. 读取 multipart 文件，要求文件存在且真实解码格式为 PNG；沿用现有大小和图片完整性限制。
3. 如果设计没有 `original_image_url`，把当前 `image_url` 保存为原图；已有原图不得被覆盖。
4. 复用现有上传存储服务保存 PNG，并将新资源作为设计的 `image_url`。
5. 设置 `transparent_background_mode=removal`、`background_removal_status=succeeded`，记录手动上传来源，清空旧错误。
6. 只更新图片、原图、透明背景和抠图状态字段，保留 `review_status`、备注和排序字段。
7. 保存成功后返回完整批次详情，前端以详情重新 hydration，确保后续任务创建读取新图片。
8. 若上传后的设计更新失败，回收本次新上传资源并返回业务错误；已有原图和旧抠图结果不变。

## 前端交互

### 下载原图

每个设计的“原图”面板显示“下载原图”按钮。下载源使用现有原图解析逻辑，先通过同源图片代理获取 Blob，再创建临时下载链接，避免远程图片的跨域 `download` 属性失效。文件名包含 Studio、设计序号和 `original` 标识。只读审核页也保留该下载入口。

### 上传手动抠图

编辑审核页的“抠图后”面板显示“上传手动抠图”按钮，绑定隐藏文件选择器，限制 `accept="image/png,.png"`。每张卡片独立维护上传中状态：当前卡片显示“上传中...”并禁用重复操作，其他卡片不受影响。

上传成功后使用接口返回的完整批次详情刷新页面，原图面板保持不变，抠图后面板显示上传 PNG，并显示“抠图完成”。失败时保留原有结果并显示“上传手动抠图失败”。只读页不显示上传按钮。

## 错误处理与并发

- 非 PNG、损坏图片、空文件或超出大小限制返回 400，设计记录不改变。
- 批次不匹配、设计不存在或自动抠图处理中返回明确业务错误，前端不覆盖本地有效图片。
- 服务端负责回收“本次上传但未能绑定设计”的资源；网络中断时前端只展示失败，不伪造成功状态。
- 手动上传完成后，任务生成读取持久化的 `image_url`；不会继续使用旧的自动抠图结果。

## 测试设计

### 后端

- 接受有效 PNG 并持久化为抠图后结果。
- 拒绝 JPG、损坏图片和空文件。
- 首次手动上传保存当前生成图为原图，重复上传不覆盖原图。
- 拒绝自动抠图 pending 设计，且不会调用上传或更新流程。
- 批次/设计校验失败不改变设计；设计更新失败会回收新上传资源。
- 更新后保留批准状态，并返回包含新图片的完整批次详情。

### 前端

- 原图面板显示下载按钮，下载使用原图地址并生成正确文件名。
- 抠图后面板显示 PNG 上传入口，非 PNG 选择被拒绝。
- 上传中只禁用当前卡片；成功刷新详情，失败不覆盖旧结果。
- 只读页可下载原图但不显示上传入口。
- 现有双图预览、自动抠图重试、批准和创建任务测试继续通过。

## 验收标准

1. 用户能从 Studio 审核卡片下载每个款式的生成原图。
2. 用户能为每个款式上传手动处理的透明 PNG。
3. 上传 PNG 会成为持久化的“抠图后”结果，原生成图仍可查看。
4. 刷新页面后结果仍存在，并能继续批准和生成 SHEIN 资料。
5. 非 PNG、并发抠图和保存失败不会破坏已有图片状态。
6. 后端相关测试、前端 Studio 测试、类型检查、构建和 diff 检查通过。
